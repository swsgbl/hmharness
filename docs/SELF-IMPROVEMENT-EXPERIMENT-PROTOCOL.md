# HMH 自进化实验协议：把“可持续变好”变成可证伪命题

版本：1.0 · 日期：2026-10-27

## 0. 重写后的任务

在不扩大功能数量、不降低门槛、不污染测试集的前提下，验证 hmharness 的学习机制能否在相同基础模型、工具、任务和预算下，产生可重复、可迁移、可审计的任务表现改善；同时让 HMH Desktop 的原生桌面交互在系统主题、键盘可操作性、减少动态效果、审批可发现性和布局稳定性方面有机器与人工可复核的验收标准。

零号原则：没有独立验证的改进只记为候选，不记为能力提升。

## 1. 顶尖专家通常额外做什么

- 预注册假设、主指标、停止规则和最小有意义效应；实验后不得为“显著”改指标。
- 冻结 baseline、模型路由、提示、环境、预算、重试策略与数据集版本；保证候选只有一个可识别的变化来源。
- 用逐案例结果、配对分析和置信区间，而不仅是整体平均数。
- 将探索集、候选选择集、内部回归集和最终隐藏留出集严格分开；隐藏 evaluator 不能被自进化进程读取或写入。
- 做阳性/阴性对照、随机化顺序、重复种子和任务族/时间维分割；排查顺序效应、模型版本漂移与 grader 偏差。
- 将安全回归、成本、延迟、重试、恢复、重复动作、工具权限拒绝等作为共同指标。
- 用独立外部评测、外部运行者和可复现的原始文件验证，不以作者生成的 task pool 单独支撑普遍化结论。
- 将失败候选、被拒原因和回滚原因公开保留，避免只发布幸存者结果。

## 2. 因果和统计设计

### 四个必要实验臂

- A0 Model-only / minimum harness：尽可能小且固定的 harness，保持环境工具可比。
- A1 Frozen HMH：冻结版本的 HMH harness/cognitive runtime。
- A2 Candidate HMH：只改变一个被检验的学习产物。
- A3 Continual HMH：A2 的通过产物与已验证经验用于下一批未见任务。

若某 benchmark 不支持 A0，写明不可比较并跳过该臂，不允许用不等价结果替代。

### 任务分割

- dev：定位错误和生成候选，可反复使用。
- selection：候选选择，可使用但必须单独标注。
- holdout：冻结模型、代码与候选后才运行；每次正式报告只打开一次。
- external/hidden：由独立 evaluator 或外部操作者持有，自进化代码不可读取/写入。

不仅随机分割轨迹，还要以任务家族、仓库、环境和时间做分组留出，避免近重复样本跨集。对真实轨迹存在用户/会话关联时，应以会话或项目为单位分割，防止同源泄漏。

### 指标

主要指标（每个项目先登记其中一个为 primary）：
- 独立 grader 定义的任务成功率 / accepted completion。
- 以任务为配对单位的候选—baseline 差异，并报告 95% 区间与每案例翻转。

共同约束：
- 平均/中位成本、输入/输出 token、墙钟延迟、工具调用数、恢复数和人工接管数。
- 安全拒绝、越权尝试、测试集访问、秘密泄漏、回滚故障（安全回归为零容忍）。
- 校准：Brier / log loss / ECE 与按环境/动作族的分组结果。校准改善独立报告，不代替成功率。
- 迁移：目标环境上 source-only baseline、target-trained upper bound、transferred candidate 的配对比较；动作字符串重叠不算迁移证据。
- 稳定性：长任务断线、重启、checkpoint、取消响应时间、重复执行和账本完整性。

### 统计方法

- 二元配对通过率：McNemar exact test；同时报告胜/负/平案例数。
- 连续指标：按任务/仓库聚类 bootstrap 的区间，避免把同一任务多次重跑当独立样本。
- 多候选比较：用预先声明的多重比较控制或顺序试验规则。
- 多种子只证明对分割/初始化稳健，不自动证明因果或外部泛化。
- 小样本一律报 NEEDS-DATA；不得把缺失值补零。

## 3. 候选产生与晋升

每一候选必须有：
- hypothesis：针对哪个失败模式，预期改变什么可观测行为。
- changeScope：允许触及的路径/对象；禁止触及 evaluator、隐藏集、凭证、审批边界和发布密钥。
- parentLineageId、源轨迹/案例 hash、变更 diff、模型/工具配置 hash。
- 训练/探测/选择结果以及逐案例错误分类。
- 适用前置条件、反例、已知退化场景。
- rollbackPlan 与发布前 snapshot。

晋升需要同时满足：
1. evaluator 的阳性/阴性对照有效；
2. primary metric 超过预先声明的最小效应或明确满足非劣标准；
3. 安全约束零回归；
4. 至少一个冻结留出门过关；
5. 成本不超预算/已声明 Pareto 点；
6. lineage 与原始证据可回放。

没有满足时保持 draft/rejected，不能通过降低阈值来制造“进化”。

## 5. 优先级和验收

P0：
- 证据快照 provenance 机器校验、JSONL 可读、文件指纹/行数/时间边界一致；
- 中断、会话恢复、工作区隔离、安全门与发布链回归必须保持绿；
- 独立 held-out / grader 不被优化器访问。

P1：
- 一个 benchmark 的 A1/A2 受控对照、逐案例报告、成本 Pareto；
- 按任务族/时间做外部泛化，建立交叉运行者复现流程；
- 把 Desktop 的主题、焦点、reduced-motion 与窗口尺寸加入真实 UI 验收。

P2：
- 多环境迁移和 2/8/24 小时 soak；
- 外部贡献者可在干净环境按命令重放原始数据。

本轮验收不能宣称 HMH 已达到 AGI；只能报告已通过的具体能力切片、置信区间、失败案例、未验证项与下一条可证伪假设。
