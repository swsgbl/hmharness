## 〇、为什么重写：审核发现了什么

全面审核没有按旧报告的建议去"提升生成质量 / 扩样本"，而是回到最底层的
原始材料——`three-arm-v2` 留在仓库里的 505 份模型原始输出——做字节级对账。
结论：**过去三轮实验的 NEEDS-DATA 不是"候选不够好"，而是测量仪器本身坏了。**

| # | 缺陷 | 后果 | 证据 |
|---|---|---|---|
| 1 | `.task` 正则断言不去 `/…/` 定界符 | 门控集 13/35 题永远判错 | 输出字节 `35 30`="50" 被判 `regex mismatch`；修复后 train 基线 53.8%→92.5%，protect 0 变化 |
| 2 | 后台环/TUI 的 `runCase` 丢弃 `skillsPrompt` | 门控一直比 A 对 A | 已发布日志 127 次晋升里 125 次基线==候选 |
| 3 | 洞察 outcome 把"没超时"记成 `ok` | impact 环按错误信号晋升/退役技能 | `turns >= maxTurns ? 'turn-budget' : 'ok'`；同文件其余三处早已用 `result.reason` |

三者已修复（PR #41）。**但修复暴露了更深的问题，这才是本计划要解决的。**

## 一、修复后的事实（全部有数据）

**事实 1：门控集失去了区分度。** train 集 32 题里 27 题稳定全过（84%），
可提升空间只剩 7.5%。protect 集 69 题里 54 题稳定全过。

**事实 2：门控修好后能检出效应了。** 对照实验（真实模型，128 runs）：
一条针对性教训让 `train-hex-3` 从 1/8 → 7/8，Fisher p=0.010。
这同时端到端验证了缺陷 2 的修复。

**事实 3：但笼统的教训总体不显著。** 同一条教训合计 46/64 vs 48/64，
p=0.842。旧门控的"零回归"规则会拒绝它——**这次拒绝是正确的。**

**事实 4：这类任务的基线本身在漂移。** 同题同模型不同时段：
`adv-long-2` 40%→75%，`cjk-ex-12` 60%→13%。精确输出格式类任务
度量的是模型输出的随机性，不是可学习的能力。

**事实 5：三个单发任务族全部天花板（仪器自验证之后）。**

| 任务族 | null 基线 | 真值 | 仪器 |
|---|---|---|---|
| 旧门控集（精确输出格式） | 92.5%（train） | 字符串匹配 | PR #41 修复后重判 505 份历史输出 |
| 手写算法题 11 道 | 98.2% | 仓库测试 | 有效 |
| 构造题（测试定义契约、从零实现） | 100%（10/10） | 仓库测试 | 自验证仪器 |

共同点：**题面把规格说全了，模型一发就做对，没有留给"教训"去补的缺口。**
（旧结论"可行路线 = 构造集"**被推翻**。构造题初版校准报的 0/5"输出被截断"，
实为校准脚本的解析器在文件内部的三反引号处提前闭合；原始响应 finish=stop、215 行完整。）

**事实 6：唯一被统计显著证明的效应是输出格式合规。** `hex-3` 的缺口是
模型爱加反引号/大写撞上 `^…$` 全匹配；那条"针对性教训"教的就是别加反引号。
真实但浅层，且属于事实 4 所说的漂移任务族。

**事实 7（最关键）：单发 bench 测的不是自进化要改的东西。**
- 自进化要改的是环境知识、工具使用流程、真实任务成功率——全是 agentic 现象。
- `skillsToPrompt` 只注入一行 `- 名字: 描述`，不带正文也不带路径；
  单发门控的 B 臂只是多了一行描述。
- 直接证据见事实 8：agentic 评测的**第一次真实运行**就发现了一个
  单发 bench 永远发现不了的生产缺陷。

**功效分析**：检出 75pp 的大效应每题 6 次；检出 10pp 需 387 次/题；
5pp 需 1500+ 次/题。三臂 v2 跑了 2020 次去追 +0.29pp——
**目标效应量在单发任务族上根本不存在。**

**事实 8：内核循环的去重环在 97.4% 的命中里返回过期结果。**
`loop.ts` 的"相同调用去重环"缓存一切成功调用 20 轮，写文件/改文件/跑命令
都不让它失效。对本机全部会话历史的审计：3521 个会话文件、57,144 次工具调用，
命中 151 次，**147 次发生在中间已有改变状态的工具执行之后**——
`run_command` 98、`read_file` 25、`edit_file` 7（编辑被静默跳过）、
`harmony_build` 4（构建工具未重新执行）；纯重复只有 4 次。
已修（`Tool.readOnly` + 世界版本失效），证据在
`website/evidence/experiments/dedup-staleness-2026-11-25/`。

**事实 9：技能正文到不了模型眼前。** 自进化晋升的技能，模型几乎从未读过。
对本机全部会话历史的审计：注入了技能的 2228 个会话里，只有 43 个（1.9%）
读到过任何 `SKILL.md`（其中还包括读其它框架技能目录的）；77 次读取里 23 次
因路径猜错失败。两处断裂：系统提示词的技能清单只有 `- 名字: 描述`，不带文件位置，
而文件分布在三个目录；技能库 120 行里 65 行的描述是字面的 `name: <技能名>`
（CRLF frontmatter 没被解析）。已修（PR #43）：清单加子目录标记、提示词给
"标记 → 路径"图例、描述提取规范化换行。证据在
`website/evidence/experiments/skill-reach-2026-11-25/`。
**这意味着**：门控修好之后，因果链在"送达"这一环仍然是断的——
学出技能 → 门控 → **送达** → 行为改变 → 结果，前面几环再严谨，送达断了就全是空的。

## 二、调研：顶尖专家会怎么做

### 2.1 一手材料（arXiv 原文，非二手解读）

- **GEPA**（arXiv:2507.19457，ICLR 2026 Oral）：反思式提示进化，
  比 GRPO 平均高 6%、最多 20%，rollout 少 35 倍。核心是**读轨迹做自然语言
  反思**，提炼高层规则。→ 对应 hmharness 的 harness 层进化。
- **Darwin Gödel Machine**（arXiv:2505.22954）：自改代码 + 基准实证验证，
  SWE-bench 20%→50%。关键是**维护档案（archive）**而非单线，且
  论文自述出现"绕过评估"的行为。→ hmharness 的 canary/pareto 已有雏形。
- **SEAL**（arXiv:2506.10943）：模型自产"自编辑"微调数据。→ 需要训练轨道，
  hmharness 当前无此能力，暂不涉及。
- **Reward Hacking in Self-Improving Code Agents**（ICLR 2026 RSI Workshop）：
  **73.8%** 的优化是"代理指标涨、真实目标不涨"；随步数从 26.4% 升到 57.8%。
  → 直接命中缺陷 3，也命中"用字符串匹配当真值"这件事本身。
- **Agent Evaluation Reliability**（arXiv:2610.00651）：可靠性取决于测量目标；
  **"加更多题"不能解决所有不确定性**；应先诊断方差来源。
- **HAL**（arXiv:2510.11977）：成本受控的第三方评估，21,730 次 rollout。
  → 客观验证的外部来源；也提示**成本要作并列终点**。

### 2.2 他们从哪些原始材料入手

轨迹（trajectory）、每次运行的原始输出、失败样本的字节——而不是汇总通过率。
本次审核两次照做两次有收获：字节对账找到缺陷 1；读第一次 agentic 运行的
工具调用序列找到事实 8（汇总数字只说"fail"，轨迹才说"它被缓存卡住了"）。

### 2.3 具体方法与工具

| 方法 | 来源 | hmharness 现状 |
|---|---|---|
| 反思式提示进化 + Pareto 种群 | GEPA | 只有"GEPA 式"祖先采样，**没有读轨迹的反思** |
| 档案式进化 + 实证验证 | DGM | pareto 池已有 |
| 代理指标 vs 真实目标分离度量 | 奖励黑客论文 | **没有**——只有一套指标 |
| 方差分解决定"加题还是加重复" | 评估可靠性论文 | B1 已做一次；未产品化 |
| 环境真值的 agentic 评测 + 仪器自验证 | Terminal-Bench / SWE-bench / HAL | 首版已有（见 B2），未产品化 |

### 2.4 客观验证标准（除你我之外谁能判对错）

| 标准 | 性质 | hmharness 可用性 |
|---|---|---|
| **环境测试即真值**（Terminal-Bench 2：89 个 Docker 任务；SWE-bench Verified：500 题） | 完全独立于本项目 | 需接入 Docker；本机 Docker Hub 不可达 |
| **HAL harness** | 第三方排行榜，支持提交自定义 scaffold | 正对应"考 harness"定位 |
| **统计显著性**（Fisher/bootstrap/McNemar，预注册） | 数学判据 | 已有 `pairedSignificance` 等但**无调用方** |
| **外部复现包 / 可重跑的审计脚本** | 他人可重跑 | 已有两个；本次新增去重环审计脚本 |

**现状的致命缺口**：单发门控的"真值"是字符串匹配，不是任务成功。
`ok` 仍 ≠ 正确。**没有外部验证器，自进化就无法证明自己真的变好了。**

## 三、重写后的计划

### 原则

1. **先修仪器，再测效应。** 仪器没修好之前跑的任何实验都不算数。
2. **真值必须来自环境，不来自字符串。** 接入测试即真值的基准。
3. **效应量先于样本量。** 先问"这个任务族有没有 30pp+ 的效应可捡"，
   再问"要跑多少次"。功效 <80% 的实验不跑。
4. **代理指标与真实目标分开度量。** 内部 bench 分数与外部基准分数并列报告，
   两者背离即为奖励黑客信号。
5. **只做能被第三方复核的结论。**
6. **仪器必须自验证。**（新）对照走完整评分路径；仪器故障单列类别；
   原始字节先落盘；解析器与独立计数交叉核对。
   *依据：同一天里"仪器坏了却被记成被测对象失败/成功"出现了十次上下。*
7. **留出真值只走产品的真实接口，并有备选解对照。**（新）
   *依据：首版真值照着参考解的形状写，agent 一份合法的通用修复被判 fail。*
8. **自进化的主度量必须是 agentic 环境真值。**（新）
   单发 bench 只留作格式合规的回归检查，不再作为门控集来源。
   *依据：事实 5–8。*
9. **留出真值只断言报告里说过的行为。**（第三次修订新增）
   真值里每多一条报告没说的要求，就是照着某一种修法写死规格。发现一个报告没覆盖、
   但真实重要的场景时，把它写进报告形成**新版本的任务**再跑；不拿新判据去判旧运行。
   *依据：`stale-dedup` 首版真值多加了两条，同一批 5 次运行被判成 2/5；
   按报告应有的真值离线重判是 4/5。*
10. **因果链的每一环都要有送达证据。**（第三次修订新增）
    *依据：事实 9——门控再严谨，技能正文到不了模型眼前就全是空的。*

### 阶段 B · 建立有区分度、真值来自环境的评估集 ← 当前

**B1. 诊断现有集的方差来源**（已完成）
- train ICC 0.64；只有 5 题同时有区分力且稳定，84 题是天花板或漂移>15pp。

**B1b. 单发任务族否定**（已完成）——见事实 5。

**B2. agentic 评测管线（主机侧首版已完成）**

设计：
- 生产 `runAgentTask` + 隔离工作区 + 隔离 `HMH_HOME`；文件工具包围栏
  （读：工作区 + 技能目录；写：仅工作区）；工具面只有
  `read_file / list_dir / edit_file / write_file / run_tests`，无 shell/网络。
- **两级真值**：`run_tests` 返回 agent 可见的测试；判定器另有留出真值。
  复现例过、泛化挂 = 只打补丁的信号。
- **四重对照**：冒烟（一句话任务须收尾）/ 阳性（参考解须 pass）/
  阴性（起始工作区须 fail 且真值真的跑了）/ 备选解（另一份独立正确实现须 pass）。
- 驱动进程内拦截越界写；编排器断点续跑、基线落盘。

结果（模型 glm-5.4，每题 5 次；两道题都取自本项目近期的真实缺陷）：

**B3. 预注册评估协议**（未开始，跑之前冻结）

### 阶段 C · 实现真正的反思式进化（GEPA 的核心）

**C0. 前置条件：技能可达（已修，PR #43；效果未测）。** 事实 9 的两处断裂已修，
但"修复后读取率升到多少"还没有数据——需要带技能的隔离环境做对照
（旧提示词 vs 新提示词）。这是进入 C1 之前的第一件事：反思器产出的规则，
首先要能被读到。

**C1. 读轨迹的反思器**。现状：`learning-loop.ts` 的"蒸馏"是把信号名包成
模板字符串 `[lesson] ${signal}`，从不读轨迹内容、不调模型、不检验效果。
目标：读失败轨迹 → 自然语言诊断 → 提炼**针对该失败模式**的规则。

**C2. 按失败模式分化的候选**（不是一条万能"精确输出"教训）。
事实 3 证明笼统教训净收益为零；hex-3 的反引号问题是**具体且可修**的。

**C3. 双门控**：agentic 内部门控 + 外部基准不退步。

### 阶段 D · 度量与诚实

- 每个候选同时报告：agentic 通过率、成本（token）、单发 bench。
- 代理与真实目标背离率作为一等指标（奖励黑客论文的核心度量）。
- 结论必须附：效应量、置信区间、功效、以及"没能证明什么"。

### 明确不做

- **不再用任何单发问答任务族建门控集。** 事实 4/5/7 + 功效分析。
- **不放宽判定器去迁就模型**（那是改考卷，正是奖励黑客）。
- **不在没有外部验证器的情况下宣称"自进化有效"。**
- **不做 SFT/RL 训练轨道**（SEAL 路线）——当前无训练能力，且与"考 harness"定位不符。

## 五、诚实的局限

- 对照实验只有 128 runs、单模型（glm-5.4）、单提供商。"教训在 hex-3 显著有效"
  成立（p=0.010），但"总体不显著"可能是样本不足而非真无效应。
- agentic 评测只跑了 2 道任务 × 5 次，同上单模型；工具面比生产窄（无 shell），
  结论不能直接外推到带完整工具的真实会话。`stale-dedup` 的 80% 只有 5 个样本
  （95% 置信区间大约 28%–99%），不能当作稳定基线。
- 修复后的门控在真实技能库上的行为**没有任何数据**：升级到 v0.23.51 后的第一轮
  进化周期跑了 30 分钟被启动器上限终止、零产出；同一时间段评测管线持续收到
  提供商 429。原因未查明。
- 技能可达性修复之后读取率会升到多少，未测（见 C0）。
- 任务取自本项目近期提交，训练数据污染风险低但未排除；更早的提交不保证。
- "三个单发任务族天花板"是对**这个模型**的结论；更弱的模型上可能有空间。
- 跨时段漂移的原因未查明（模型版本更新？采样参数？提供商路由？）。
- 生产 `chat()` 不读 `finish_reason`，提供商截断时不可见。实测不带上限时
  默认上限 ≥8648 completion tokens，未证明会咬到现有任务，故暂未改。
- 去重环审计来自一台维护者机器的会话历史；其它使用者的比例可能不同。
  过期判定按工具名保守分类，只会高估不会低估。
- 开发机上有常驻守护进程（进化/web/扩展桥）在写自己的状态文件，
  "评测没有碰真实状态"的核对需要按修改时间和内容逐条判读；
  驱动进程内的越界写拦截是更硬的那一道，但测试子进程仍是只记录不拦截。
