## 1. 问题陈述

- v2 的 NEEDS-DATA 精确含义:**不是样本不足**。B-vs-A @protect 的 CI 已收窄到 2.32pp(v2 §一);缺的是 C 臂数据——4 个分型种群候选全部被门控拒绝,拒因一致 "below quality floor (0.46 < 0.60)",candidate=baseline=46%,零回归零提升(v2 §一),C 臂 505 格全占位(v2 §三)。
- 瓶颈定位(v2 §六):生成器产出质量 × 门控基线绝对水平的组合;**继续无差别扩样本不改变本结论**。
- 为什么"再来一次同样的实验"没有信息量:样本轴已走完(v1 的唯一下一步建议"protect ≥60 + 5 seeds"已被 v2 执行:23→69 题、3→5 seeds,v2 报告头);候选多样性轴也已走完("分型×多候选×双角度"种群仍全拒,v2 §一)。在两条已穷尽的轴上重复,只能重演同一 NEEDS-DATA。
- 结构性事实:门控地板 0.60 为绝对值(POP);gate 基线 v1 未脱敏 53.8%(v2 偏差 1)、v2 脱敏后 46%(v2 §一),距地板 6.2pp / 14.0pp(算术)。弱基线下门控只输出"拒",不输出候选间优劣的梯度信息。

## 2. 设计甲:失败分型感知的候选构造

- **假设**:候选无效的根因可分型;按型注入结构化约束的定向生成优于盲目变异。分型从 v2 的 judge 输出层(format/exact-output 等 5 类,实际激活 2 类,v2 §一/偏差 2)下沉到**生成缺陷机制层**,四型及实测锚点:
  | 型 | 证据锚点(实测) |
  |---|---|
  | 前置条件缺失 | 技能盲触发:terminal 盲发包含率 0.486 vs 前置条件匹配 0.872(P1-2 §一) |
  | 变量绑定错 | 程序体纯字面 n-gram:乱序轴 15/47 全步在场但乱序(P1-2 §七) |
  | 触发漂移 | 匹配率 M1=0.364/0.190/0.400;terminal 64% 轨迹被拒触发(P1-2 §一/§二) |
  | 验证缺失 | 候选无自检步骤;失败样本池:v2 train 失败 format 14 题+exact-output 3 题(v2 §一) |
- 分型输入=skill-gen 失败轨迹(历史门控包含率 0.39、当前同口径 0.486,P1-2 §三)并与三臂 phase0 train 失败对照;四型映射候选技能的解剖结构(前置条件字段/参数化占位/触发条件/自检步骤)。分型为本地确定性计算、零 token(照搬 P1-2 §六纪律);API 成本只在候选生成与门控。
- **臂定义**:A/B/C 逐字继承 v1/v2(A=冻结技能快照;B=train-only 同族教训临时注入;C=过门候选全局注入,GATE 模块头注)。
- **与 v1/v2 的差异**:仅 phase1。每型定向生成 2 候选(四型共 ≤8,继承 POP.perClassCandidates=2),生成 prompt 按型携带结构约束(前置条件缺失型→前置条件字段;变量绑定型→参数化占位;触发漂移型→触发条件收紧;验证缺失型→输出自检步);全种群一次进同一 runEvolution,门限零改动(quality floor 0.6/零回归/双采样/holdout 复验/成本帽,POP.gate)。
- **主终点**:不变——protect 集环境真值成功率 C-vs-A 配对(bootstrap 95% CI + 逐 seed McNemar;α=0.05、protect 回退 ≤3pp、成本增长 ≤10%,GATE 常数)。
- **次级终点(新增:分型命中率)**:候选声称修复的失败样本,带候选注入复跑后转成功的比例;对照 A 臂同格复跑,逐样本 McNemar,并扣除 null 翻转带(v2 train 翻转率 9.4%,v2 §一)。判定线:该型失败样本 ≥5 才判(low-power 线,沿用 P1-2 low-power 纪律形状;5=预注册常数);命中率 ≥0.5 记"该型命中"(预注册常数)。
- **admission/停止**:cArmRule 继承(种群全拒→C 臂 not-deployable→主终点 NEEDS-DATA,POP.allRejected);新增停止条件:定向候选 train 通过率与 baseline 差 0pp(v2 模式重演)→甲假设证伪,不追加候选轮。
- **预算**(任务集不变):phase0 505 runs ≈1.44M token、phase3 A/B 1010 runs ≈2.93M(v2 §三实测同规模),合计 ≈4.37M(v2 偏差 4);C 若部署 +505×2,900≈1.46M(单 run 均值 2,928,997/1010≈2,900,算术);生成+门控 token 历来不落盘(v1 偏差 4/v2 偏差 3),按 ≤8 候选 ×35 题(v1 偏差 2 门控集结构)×2 采样 ×2,900 ≈1.62M 列算术上界。carry-over 条款:v2 phase0 的 A 臂 null 与本轮 datasetHash/seeds 一致,可预注册复用省 1.44M——默认保守重跑,复用须冻结时明示。

## 3. 设计乙:基线任务集升级

- **假设**:门控全拒的主因是 gate/train 基线绝对水平过低,使绝对地板无差别否决;任务难度校准后门控恢复辨别力。v2 偏差 1 已证主因之一:脱敏使 beh 族对称失效,gate 基线从 53.8% 降至 46%。
- **对象是 gate/train 侧,不是 protect**:protect 69 题 CI 已 2.32pp(v2 §一),主终点效力足;弱的是门控基线。
- **扩法(预注册)**:train 32→64;来源优先级:①HarmonyBench v1.0.0 未用离线可判题(v2 已用 46 入 protect、8 needsTools 排除,v2 §三;剩余容量=事实清单 2)②hmb bench 未采样族题 ③不足则按注册任务协议新编。选择规则一次冻结入 manifest;预置全部 seedCases 防 v1 偏差 2 重演(gate 评测集被自动扩种);beh 族脱敏失效二选一预注册:修 prompt 路径占位可解析,或整族排除留痕。
- **校准即 phase0**:候选新题先跑 A 臂预跑,任务级通过率 40–70% 为有效难度带(判据带,预注册);预跑数据即 phase0 对应格,不重复烧。诚实注记(算术):地板跨越另需聚合基线 ≥0.60−增益;已实测增益量级=B 臂 train +4.2pp(v1 §一)/+2.5pp(v2 §一),故现实晋升需聚合基线 ≥约 56%;40–70% 带只保证任务有梯度,不保证地板可跨——两事分开陈述。
- **防掩盖效应(审计03 P2-2 红线:新增域必须先加入注册任务和独立评估协议,禁止用更大任务集掩盖效应)**:①新题先冻结入 datasetHash(buildTaskSetHashV2 重算)后跑;②protect 集与主终点定义零改动;③gate 判定新旧分层双报,禁止只报合并集,只在新题过而旧题回归→REJECT;④门限零改动。
- **统计**:compareArmsV2 协议逐字沿用(seeds=5)。
- **admission**:升级后聚合 gate 基线 ∈[40%,70%](预注册判据带)。落带失败**不许现场换题凑带**——选择规则一次冻结,失败即触发 F1(§6)。
- **门控辨别力探针(乙先行产出)**:把 v2 同款 4 候选在新基线上重过一次门控(零生成成本;≈4×35×2×2,900≈0.81M,算术);若指挥者要完整方差曲线(v2 §六 第一优先:同一候选多次门控的晋升率波动),加测至 3 次。探针仍全拒且零分化→门控辨别力假设证伪。
- **预算**((64+69)×5,算术):phase0 665 runs ≈1.90M(单 run 2,857=v2 §三 phase0 实测均值);phase3 A/B 1330 runs ≈3.86M;C 部署 +1.93M;门控上界 1.62M+探针 0.81M;上界合计 ≈10.1M ≈2.3× v2 实测 4.37M(v2 偏差 4)。carry-over:protect 侧 A 臂与 v2 同格,复用条款同甲(默认重跑)。

## 4. 推荐:串行,先乙后甲

- ①甲的可判定性依赖乙:v2 证据表明 46% 基线下门控不产生候选间梯度信息,甲直接跑大概率重演"全拒+NEEDS-DATA",≈4.4M token 换零新信息;②乙直接执行 v2 §六 第一优先(门控基线方差/弱基线与地板的结构性距离),且自带廉价探针,先验证"门控有辨别力"这一共同前提;③并行不可取:甲在旧 train 上分型构造、乙换 train 集,协议互相污染,预算叠加;④先甲后乙仅在指挥者愿为甲的次级终点(分型命中率,不依赖门控辨别力)单独付一轮时成立。
- **指挥者决策最小事实清单**(冻结前补齐,均为现存数据导出,零实验):1) v2 门控逐题通过表(phases/2-gate*.json):46% 的构成=脱敏 beh 失效题 vs 真难题各占多少;2) HarmonyBench v1.0.0 池与 hmb bench 的剩余可扩容量及难度分布;3) 候选生成+门控 token 实测(历史无落盘不可回补,下轮起须落盘);4) 四失败型在语料中的分布(甲 phase1 首测)。

## 6. 诚实边界与整线证伪条件

- **本轮仍答不了**:①真实用户轨迹分层(两轮均标不适用,v1/v2 NEEDS-DATA 清单③);②单模型单提供商外推(v1 §六);③生成/门控 token 实测(无落盘);④分型命中率无历史基线(本轮为首测);⑤40–70% 带是设计判据非实测曲线——若落带后门控仍无辨别,判据本身被证伪并记录;⑥触发真值仍是包含率代理,活体验证缺(P1-2 §七 局限④)。
- **整线停止(证伪)条件**:
  - **F1(乙)**:预注册选择规则跑完,聚合 gate 基线仍落不进 [40%,70%] →"基线可升级"证伪;三臂线冻结,转 v2 §六 的门控方差研究线。
  - **F2(甲)**:门控有辨别力(探针分化)后,定向候选仍全拒且 train 差 0pp →"失败分型可驱动有效候选"证伪;C 臂线停(B 臂与技能次级终点线不受影响)。
  - **F3(协议)**:主终点连续第三轮 NEEDS-DATA →指挥者评审三臂协议本身的存续。
  - **F4(预算)**:任一轮超预注册上界未出可判定数据 →硬停。
