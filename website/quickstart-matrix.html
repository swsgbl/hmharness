标准桌面复现命令

先做这组无模型检查，再进入 hmh init 和厂商配置；可把 prefix 换成任意空目录，避免污染全局环境。

node --version
npm --version
npm view @hmharness/cli@0.23.50 version engines bin --json

npm install --prefix ./hmh-smoke @hmharness/cli@0.23.50
npm list --prefix ./hmh-smoke @hmharness/cli

# Windows
set HMH_HOME=%CD%\hmh-smoke-home
.\hmh-smoke\node_modules\.bin\hmh.cmd --help
.\hmh-smoke\node_modules\.bin\hmh.cmd check
.\hmh-smoke\node_modules\.bin\hmh.cmd devices

# macOS / Linux
export HMH_HOME="$PWD/hmh-smoke-home"
./hmh-smoke/node_modules/.bin/hmh --help
./hmh-smoke/node_modules/.bin/hmh check
./hmh-smoke/node_modules/.bin/hmh devices

全局安装后等价检查是 npm list -g @hmharness/cli、hmh --help、hmh check、hmh devices。提交反馈时粘贴 OS/Node、npm list 结果、脱敏后的 check 输出和第一个卡点，不要粘贴 API key、cookie、私人路径或设备/账号标识。

首错分流

安装 / 入口

  • Unsupported engine：先升级 Node 到 22+，再重试。
  • hmh: command not found：核对 npm 全局 bin 目录是否在 PATH；隔离 prefix 用户直接调用 node_modules/.bin 下的入口。
  • 需要确认版本：使用 npm list -g @hmharness/cli，不要把交互 REPL 当作版本命令。

工具链 / 设备

  • hmh check 缺 hdc、hvigorw 或 ohpm：先安装或配置 SDK/DevEco CLI，再复跑 check。
  • 单项工具探针失败：保留原始第一行错误并附 OS/Node 与工具版本，反馈到环境 Discussion。
  • hmh devices 无设备：先启动模拟器或接入已授权调试设备，再复跑 devices；这不需要模型配置。
